# vertex-ao-baker

纯 Python + NumPy 的 CPU 顶点环境光遮蔽（AO）烘焙库，面向游戏场景网格。
基于 BVH 加速的半球射线采样，支持距离衰减、UV 拆分重复顶点合并，
并对开放边界、退化三角形和重叠表面给出明确行为。

## 快速开始

```python
import numpy as np
from vertex_ao import bake_vertex_ao

result = bake_vertex_ao(
    positions,      # (N, 3) 世界空间顶点坐标
    triangles,      # (M, 3) 三角形索引
    normals,        # (N, 3) 顶点法线（无需单位化，但不能为零向量）
    num_samples=64, # 每个顶点的半球采样射线数
    max_distance=5.0,  # 最大射线距离（超出视为天空可见）
    falloff=1.0,    # 距离衰减指数
    seed=0,         # 随机种子：相同输入 + 种子 => 完全相同的结果
)

ao = result.ao    # (N,) 每个输入顶点的 AO，1.0 = 完全无遮挡
```

运行测试：

```bash
python -m unittest
```

## 半球采样

每个顶点围绕其法线生成**余弦加权半球**方向（`u1, u2` 均匀随机，
`z = sqrt(1 - u1)`），即靠近法线方向采样密度更高，与漫反射
余弦项匹配，同等采样数下方差更低。随机数由
`numpy.random.default_rng(seed)` 产生，烘焙完全确定：
相同网格、参数和种子重复烘焙结果逐位一致（测试
`test_rebake_is_deterministic` 覆盖）。

单条采样射线的可见度：

- 未命中（含命中距离超过 `max_distance`）：贡献 `1.0`；
- 命中距离 `d`：贡献 `1 - (1 - d / max_distance) ** falloff`。

顶点 AO 为所有采样贡献的平均值，范围 `[0, 1]`。`falloff` 越大，
只有非常贴近的几何体才会产生明显变暗；`falloff = 1` 为线性衰减。

## 法线方向

- 采样半球严格沿**顶点法线**一侧展开，因此法线方向直接决定
  哪一侧被计入遮蔽。法线必须指向"外侧 / 可受光"一侧（与渲染
  法线一致）；法线反了会导致墙角变亮、开阔面变暗。
- 法线无需单位化（内部会归一化），但零向量会抛出 `ValueError`。
- 三角形求交是**双面**的：背面朝向的墙、薄板同样产生遮蔽，
  不依赖绕序。

## 重复顶点合并（接缝连续性）

UV 拆分 / 硬边导出的渲染网格中，同一世界位置常有多个顶点。
烘焙前按**量化后的 (位置, 法线)** 对顶点分组（容差
`position_tol=1e-5`、`normal_tol=1e-4`），每个唯一组合只追踪
一次射线，结果广播回所有重复顶点，因此接缝两侧 AO 逐位相等
（`test_uv_split_seam_is_continuous`）。位置相同但法线不同的
顶点（硬边）**不会**合并，各自独立烘焙。

## 边界情况行为

- **开放边界**：不做任何边缘延拓或人为压暗。射线未命中任何
  三角形即为天空可见（贡献 1.0），半开网格边缘顶点自然更亮。
- **退化三角形**（零面积）：构建 BVH 时剔除，永不产生遮蔽；
  数量记录在 `result.stats["num_degenerate_triangles"]`。
- **重叠 / 共面表面**：射线原点沿法线偏移 `ray_epsilon`
  （默认场景对角线的 1e-4），且 `t <= ray_epsilon` 的命中被忽略。
  因此与着色点共面的 z-fighting 重复几何不会自我遮蔽，
  而位于偏移半球内的真实几何正常产生遮蔽。
- **自相交**：同一三角形对从自身顶点发出的射线同样被
  `ray_epsilon` 过滤，地面不会被自己压暗。

## 可接受的烘焙耗时

纯 Python 射线循环，复杂度约为 `O(顶点数 × 采样数 × log 三角形数)`。
参考值（本仓库 CI 容器，单核）：

| 场景规模 | 采样数 | 耗时 |
|---|---|---|
| 单元测试全集（13 个用例） | 32–64 | ~3 秒 |
| 629 顶点 / 1154 三角形 | 32 | ~2.5 秒 |
| 629 顶点 / 1154 三角形 | 64 | ~3.5 秒 |
| 629 顶点 / 1154 三角形 | 128 | ~8 秒 |

经验范围：**每千顶点 × 64 采样约 5–10 秒**属正常。关卡级网格
（数十万顶点）建议分块烘焙、降低采样数后配合 denoise，或把
`bvh.closest_hit` 换成 C 扩展；API 不需要变化。

## 项目结构

- `vertex_ao/bvh.py` — 中位数切分 BVH，Möller–Trumbore 双面求交，
  最近命中查询。
- `vertex_ao/baker.py` — 顶点合并、余弦加权半球采样、AO 累积与
  `BakeResult`。
- `test_vertex_ao.py` — 地面无遮挡、墙角变暗、遮挡板距离衰减、
  半开网格、重复顶点接缝、重复烘焙一致性等 13 个单元测试。
